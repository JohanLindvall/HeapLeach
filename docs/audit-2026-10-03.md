# Service audit — 2026-10-03

This review started from `4fbb79c` on `main`. It covers the service lifecycle,
HTTP client and API, queue persistence and admission, native transfers,
external helpers, shared extractor dispatch, command-line behavior, frontend
submission and state recovery, build portability, dependencies and documentation.
The work prioritizes observable failures, bounded resource use and preserving
downloaded data. It does not establish that every live host still works.

The strongest existing parts are the native transfer engine's resume checks,
filesystem confinement with `os.Root`, cancellation ownership, generation-aware
job resolution, atomic settings changes, and full-snapshot recovery after a
missed SSE patch. Existing tests exercise these invariants extensively. The
fixes below preserve those mechanisms and add coverage around their boundaries.

## Data integrity and correctness

| Finding | Change | Regression evidence |
|---|---|---|
| Failed queue restoration was followed by saving an empty/new queue over the unreadable original. This also affected files written by a newer state version. | A restore error disables persistence for that process and explains why. Periodic and shutdown saves both preserve the original. | `TestRestoreSurvivesAnUnusableFile` checks the bytes after both saving paths. |
| A custom state path ending in `.zst` could adopt and later delete the neighbouring suffixless file. | Migration is explicitly configured only for the default queue location. | Custom-path non-adoption and default migration tests in `persist_test.go` and `config_test.go`. |
| State input was read in full before the decompression limit applied. | Check regular-file size before reading its contents; bound the read and serialized JSON as well as decompression. | A sparse oversized file is rejected without allocating its advertised size. |
| Two listing entries with the same sanitized name and exact size could be treated as the same completed file. | Reserve all original destinations, then number collisions before workers start. Late resolver names and disposition headers cannot undo that allocation. | `TestSameNamedListingEntriesKeepDistinctBytes` transfers distinct equal-length payloads, checks contents, reserves an existing numbered name and verifies repeat submission. Portable paths and long UTF-8 names are covered separately. |
| HTTP 202, 204 and 205 could pass as completed native files or playlist parts. | Native file transfers require 200 or a validated 206. Playlist parts require 200. | `TestTransfersRejectNonFileSuccessResponses` also checks that refusal creates no part file. |
| Retrying a held, queued item from a restored job was rejected as already in progress. | Check whether the job needs re-extraction before refusing an ordinary queued-item retry. | Restored-item retry tests cover queued, failed and canceled items. |
| Source-resolution failures with no items, and mixed accepted/rejected CLI inputs, could exit successfully. | The closing result accounts for failed sources and rejected inputs, not just failed files. | CLI integration tests and smoke tests against the built executable check exit codes 0 and 1. |

The destination allocation is deterministic for the same listing order. It is
not a content-identity database: reordered duplicate entries, identical names
from separate jobs, and destinations discovered only later remain important
limits of the name-and-size skip policy.

## Security and resource bounds

| Finding | Change | Regression evidence |
|---|---|---|
| Browser-shaped TLS requests could bypass an explicitly configured proxy. | Consult the standard transport's proxy selection first. A proxied request uses that transport, including CONNECT and `NO_PROXY` handling. | `TestBrowserTransportHonoursProxy` verifies a CONNECT attempt and zero direct dials when the proxy refuses. |
| The shared cookie jar lacked a public-suffix policy. | Use `publicsuffix.List`. | A cookie for a public suffix is rejected while a valid parent-domain cookie is retained. |
| An explicitly supplied referrer survived an HTTPS-to-HTTP redirect. | Remove it on a TLS downgrade and exclude it from header restoration. | TLS-to-plaintext redirect fixture checks that no referrer arrives. |
| A streaming error body could remain silent indefinitely before transfer monitoring began. | Bound non-file response bodies by the HTTP client's timeout while leaving successful media bodies streamable. | Silent 202, 403 and 503 fixtures expire before their parent context. |
| Submitting many sources immediately started every expensive listing. | Admit at most four active source resolutions, separately from transfer concurrency; waiting work is cancelable. | A saturated fixture verifies the active bound and proves canceled waiting work never reaches the network. |
| Nested source delegation could revisit itself or form arbitrarily deep chains. | Carry path-local ancestry through the registry, reject cycles and cap nesting at 16. Route AlohaTube delegation through the same entry point. | Cyclic and changing-URL recursive fixtures stop at the intended boundary. |
| Metadata and helper diagnostics could grow memory without bounds; metadata had no fixed wall-clock deadline. | Share helper execution, bound metadata to two minutes and 8 MiB, and retain only bounded diagnostics while continuing to drain output. | Portable helper-process fixtures exercise success, oversized output, nonzero exit and cancellation. |
| Helper children could outlive cancellation or leave progress pipes open after the parent exited. | Share Unix process-group cancellation, a five-second inherited-pipe deadline and failure cleanup. Read external progress concurrently with `Wait` so that deadline can run. | Tests exercise child termination on cancellation and wait expiry, plus the complete external-download progress/file path. |
| Remote filenames, notes and errors could issue terminal controls or insert screen rows. | Sanitize untrusted fields before adding the renderer's own ANSI codes. | CLI tests include ESC, OSC, C1 controls, line separators and ordinary Unicode. |
| Ordinary server request bodies/replies had no overall read/write deadline. | Add 30-second deadlines while retaining SSE's per-write deadline. | The actual executable remains readable over SSE beyond the ordinary deadline. |
| Framing and response policy were not applied consistently. | Add framing denial, a narrowly scoped CSP, `nosniff` and no-referrer headers across responses. Keep the existing cross-origin mutation protection. | Handler tests and executable smoke checks cover the headers and cross-origin rejection. |

The cookie policy follows the [Go cookiejar contract](https://pkg.go.dev/net/http/cookiejar#Options).
Helper waiting follows the distinction between process exit and inherited
pipes in [os/exec](https://pkg.go.dev/os/exec#Cmd).

## Usability, feature behavior and HTTP semantics

- Partial form success now retains rejected URLs. Edits made while a request is
  pending remain intact. A ref-based lock prevents duplicate submission before
  React repaints, including while clipboard permission is pending. Four DOM
  tests exercise these behaviors using React's `act` and jsdom.
- An event connection that never delivers its first snapshot now times out,
  reconnects and starts polling. Merely receiving connection headers no longer
  stops polling or declares the view live. Two additional recovery tests cover
  these cases.
- Source links encoded with the internal `links:` scheme open their underlying
  HTTP(S) page. Unsupported browser schemes do not become clickable targets.
  URL conversion tests preserve query escaping and both HTTP and HTTPS forms.
- Unknown API paths return 404, unsupported methods return 405, and missing
  built assets return 404 rather than a successful HTML page. Oversized JSON
  bodies return 413, including oversized trailing whitespace. Settings remain
  unchanged after a refused request.
- Both compressed and uncompressed state/event responses advertise
  `Vary: Accept-Encoding`.
- YouTube playlist probes use the configured file cap at yt-dlp, with one
  sentinel entry to detect truncation. A partial result is labelled beside the
  title without changing its destination folder. Single-title probes disable
  playlist expansion. URL arguments follow `--` in metadata and download calls.
- README and control tooltips now distinguish built-in transfer controls from
  external helpers. Running helpers do not obey native mid-transfer pause,
  speed limits or stall monitoring. The POSIX-shell requirement is explicit.
- README documents API authority, loopback/private-network deployment, proxy
  behavior, failed-state recovery and the limits of fresh-clone live tests.
  `CLAUDE.md` records the new invariants for subsequent changes.

Shared process execution and bounded output live in `internal/tools` and
`internal/util`; callers no longer duplicate their cancellation setup.
Operational ceilings remain in `internal/config/limits.go`. No new Go runtime
dependency was needed. jsdom is a frontend development dependency only.

### Dependency scans

The Go source scan reports no reachable vulnerabilities and no affected
imported packages. It lists one module advisory:
[GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932), concerning the unmaintained
OpenPGP packages in `golang.org/x/crypto`. `go list -deps ./cmd/heapleach` contains
none of those packages, and scanning an unstripped Linux executable also
reports zero affected symbols/packages.

Scanning the stripped release-style binary reports that advisory as affected.
This is a scan limitation, not a second clean result: govulncheck documents
module-wide reporting when it cannot extract symbols. The source dependency
graph and unstripped binary provide the evidence for assessing this particular
report as inapplicable. Keep both results visible when adding vulnerability
checks to CI. See [govulncheck's limitations](https://pkg.go.dev/golang.org/x/vuln/cmd/govulncheck#hdr-Limitations).

## Remaining work and operating limits

1. **Public deployment needs authentication outside the process.** The API can
   start network requests and change writable destinations. The normal service
   listen address is all interfaces; browser-origin checks are not login.
   Keep it private or use an authenticated reverse proxy and restrict backend
   access. A future multi-user product needs a separate authorization design.
2. **Content identity remains approximate.** Name plus exact length can skip a
   different same-sized file already on disk. Stable source identifiers and a
   persisted destination manifest would improve cross-job and reordered-listing
   behavior. MEGA's per-file MAC remains deliberately unverified by the existing
   implementation; decryption does not provide that integrity check.
3. **External helpers remain a distinct execution path.** Native throttling and
   pause do not govern them; non-Unix cancellation cannot kill a Unix-style
   process group. A native Windows launcher and equivalent transfer controls
   need dedicated work and operating-system tests.
4. **Bounds are per operation, not a global memory quota.** The queue can contain
   many jobs, waiting resolvers still have goroutines, state allows up to 1 GiB,
   and an HLS part may occupy up to 256 MiB per concurrent fetch. A byte-budgeted
   assembler/spill-to-disk design and total queue admission policy would make
   extreme workloads more predictable. This audit did not perform a sustained
   maximum-concurrency memory soak.
5. **Terminal width is approximate.** Controls are now safe, but rune counts do
   not model wide characters, combining sequences and emoji grapheme widths.
   A dedicated terminal-cell implementation is still needed for exact alignment.
6. **Browser testing has boundaries.** Component submission and state recovery
   are covered; full real-browser layout, screen-reader operation, browser
   clipboard policies and very large virtualized queues still need dedicated
   end-to-end and accessibility testing.
7. **Host correctness needs controlled live fixtures.** Fresh fixture tests
   cannot verify anti-bot changes, signed-link expiry, real range responses or
   remote account limits. Supply sources through the ignored live tests and
   fetch bytes as well as metadata, following `CLAUDE.md`.
8. **Helper releases are still mutable upstream inputs.** `make dependencies`
   and container helper downloads use latest upstream assets. Reproducible,
   independently verified helper pinning requires an update/checksum policy;
   it was not introduced by this audit.
